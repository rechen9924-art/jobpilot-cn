# 通用简历字段集 (resume.schema.json)

> 这是求职 skill 的**数据枢纽**。它不写死任何人的数据，只定义「一份简历该有哪些块、每块什么字段」。
> 简历基础稿、两种 intake 模式、方向派生、模板渲染、ATS 兼容性（渲染兜底）——全部基于它。

---

## 1. 为什么要有它（设计原则）

求职 skill 的顶层模型应当是 **「养基础稿 + 按方向派生」**，而不是「一次性变换」。
这份 schema 就是那个**唯一的基础稿结构**：

- 用户的数据填进 schema → 成为该用户的「基础稿」；
- 同一份基础稿 → 按不同投递方向派生出 tailored 版（换标题/人设/排序，不编新事实）；
- 模板渲染、ATS 兼容性（渲染兜底）都读这份结构，只算一次、处处复用。

这样设计天然强制「不虚构」：派生只是同一批事实的换序/换重/换标题，不是新编内容。

---

## 2. 字段总览

| 块 (key) | 必填 | 含义 | 派生时怎么动 |
|---|---|---|---|
| `basics` | ✅ | 基本信息：name / title / phone / email / location（+可选 wechat / links） | `title` 按方向改方向词与顺序 |
| `summary` | ✅ | 个人简介 2-4 句，含可量化亮点 | 可重述人设，不编数据 |
| `experience` | ✅ | 工作经历数组，每条含 company/role/dates/bullets | 条目可重排；bullet 可重排/筛选 |
| `skills` | ✅ | 技能，按 category 分类的数组 | 分类顺序、归类、按方向增删 |
| `education` | ⬜ 建议 | 教育背景数组：org/title/year | 一般不改 |
| `projects` | ⬜ 可选 | 独立项目：name/role/tech/description | 可前置最能佐证方向的项目 |
| `extra` | ⬜ 可选 | 证书/语言/获奖等开放结构 | 按需 |

字段的精确类型、required 约束、描述见 [`resume.schema.json`](./resume.schema.json)（JSON Schema draft-07，可用于程序校验）。

## 3. 两种 intake 模式（都靠这份 schema）

### 模式 A：用户自带简历
```
用户丢简历（PDF/Word/文本）
   → 解析抽取
   → 归一化进 resume.schema.json 的结构
   → 字段缺失 → 标记待补清单
   → 校验通过 → 存为用户「基础稿」
```

### 模式 B：引导生成
```
把 schema 的 required 字段作为引导表单发给用户
   → 用户逐项填写（姓名/求职意向/电话/邮箱/所在地 + 简介 + 经历 + 技能）
   → 填完即为基础稿
   → 可选补充 教育/项目/附加
```
脱敏示例见 [`example-cv.json`](./example-cv.json) —— 用它当表单模板或占位演示，里面是 `(示例) 张三` 的假数据，**不含任何真实个人信息**。

**两种模式殊途同归**：都产出一份符合本 schema 的基础稿文件，后续流程完全一致。

---

## 4. 方向派生（基于 schema 的呈现层，不改事实）

派生配置是一个独立层，引用本 schema 的字段来控制呈现。**派生的输入是用户自由填写的投递意图，skill 不内置固定方向模板（如 'AI 版' / '外贸版'）——结构本身不预设方向。**

- `title`：按投递方向重写方向词与顺序（方向由用户意图驱动，例如用户投递某 AI 业务岗时可重写为「AI 业务自动化 · 外贸智能化 · 海外获客」）；
- `summary`：可重述人设，但不得编造新数据；
- `skills[].category`：按方向重排分类顺序、调整归类；
- `experience[].bullets`：按方向重排/筛选 bullet；
- `projects`：可前置最能佐证该方向的项目。

> 红线：**派生绝不新增未经验证的事实**。同一批事实只换呈现，不换内容。

---

## 5. 通用红线（适用于所有人）

- **不虚构**：不编经历、数据、技能；没有的数字不写；技术栈只写真实用过的。
- **禁署名**：对外产物（PDF / Word）严禁工具署名、生成声明、版权水印。

---

## 6. 与现有项目文件的关系

| 路径 | 角色 |
|---|---|
| `schema/resume.schema.json` | **通用枢纽**（本文件）—— 结构定义，无个人数据 |
| `schema/example-cv.json` | 脱敏示例 / 模式B 表单模板 |
| `data/cv-base.json` | 某个用户（示例作者）的基础稿实例，符合本 schema |
| `data/cv-*.json` | 用户按方向的派生实例，同样符合本 schema |
| `templates/` + `scripts/` | 读 schema 结构渲染为 PDF / Word |

要接入新用户：让他走模式 A 或 B 产出一份符合 schema 的基础稿，丢进 `data/`，即可复用全部渲染/评分能力。
