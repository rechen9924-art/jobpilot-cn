# 模式：关键词审计与技能认领（keyword-audit）

国内招聘平台（BOSS / 猎聘 / 脉脉）的 HR 搜索与 ATS 解析都依赖关键词。本模式做两件事：**反推高频词找缺口** + **列出你可能做过但没写的技能让你认领**。

## 输入

- **简历**：`data/cv-base.json`
- **目标职位**（或通用方向）；有真实 JD 优先喂 JD（词频反推更准）

## 输出 1：高频关键词表（约 25 个）

- **来源标注**（诚实性）：
  - 无 JD 时：基于典型 JD 归纳（**非平台真实搜索量**）；
  - 有 JD 时：基于 N 份 JD 词频反推，标注「基于 N 份 JD」。
- **两档对照简历**：
  - ✅ **可补**（简历有证据支撑）→ 标注「放哪」：skills 栏 / 经历 bullet / summary；
  - ⛔ **不补**（简历无证据）→ 写明原因，防硬凑露馅（如报关 / 单证 / 跟单 / 供应链 / RPA，无证据坚决不写）。

## 输出 2：技能认领清单（防漏写）

针对方向列出常见技能，请用户逐一确认「做过 / 没做过 / 做过但不深」，**确认「做过」才补进 skills（措辞准确不夸大）**。

**外贸 / 跨境方向参考清单**
- 出口报关（报关单 / 资料 / 货代对接）
- 外贸单证（信用保障线上单证 / 信用证交单）
- 订单跟单（排产 / 验货 / 订舱出货）
- 供应商开发与管理、生产排程
- 询盘转化、海外客户开发

**AI / 自动化方向参考清单**
- RAG / 检索增强生成（是否先检索知识库再答）
- OCR / 单证识别
- 低代码平台（n8n / Dify / Coze）—— 与「纯 Python 自动化」的区别需澄清
- AI 翻译 / 多语言本地化（是否专门做翻译流）
- AI 视频 / 数字人 / 剪辑自动化
- BI 看板（PowerBI / DataV）—— 与「Excel 可视化」区分，无专业 BI 经验不写
- ML 预测模型（销量 / 选品预测）
- RPA 工具（影刀 / UiPath / 按键精灵 / Playwright / Selenium）—— 代码级 vs 拖拽式需澄清

## 匹配率计算（语义覆盖率，ATS 生死线）

> 市场实测：ATS 按 JD 关键词匹配初筛，**匹配度 <60% 的简历会被直接淘汰**；2026 语义搜索不再吃「堆关键词」，而是看关键词是否嵌在「动作+结果」语境里。

**算法**：

1. 从目标 JD 抽取**核心要求清单**（去重）：硬技能、工具/平台、职位名、证书、行业术语、年限。
2. 逐条判定在简历（cv-base.json）中的状态：
   - ✅ **命中**：简历有同款/近义词且有证据支撑（出现在 skills 或经历 bullet）；
   - ⚠️ **部分**：相关但不强、或埋在尾部未强调；
   - ❌ **缺失**：简历无任何对应内容。
3. **匹配率 = 已命中条数 ÷ 核心要求总数 × 100%**（⚠️ 计 0.5 条，❌ 计 0 条）。
4. 标定门槛：
   - **≥80%**：强匹配，可直接投；
   - **60–79%**：可投，但优先把 ⚠️ 补成 ✅、❌ 如实标注；
   - **<60%**：**高风险**，大概率过不了初筛——要么补强证据，要么换更匹配的岗位，不要硬投。

**嵌入纪律（防堆砌翻车）**：

- 把 ✅/⚠️ 关键词**自然写进经历 bullet 的「动作+结果」里**（如「用 Python 自动化报关台账，月省 20 小时」），而非单列「技能：Python」式堆词；
- 绝不白字堆关键词、不造隐藏关键词段（现代 ATS 标 Low Trust）；
- 相邻能力也可补（如 Data Scientist 补「业务方沟通」），提升语义覆盖。

## 复用

- 关键词提取逻辑复用 `oferta.md` 的 JD 解析；
- 补词后由 `pdf.md` 渲染验证，确认排版无溢出。

## 诚实性红线

- 凡标注「可补」必须用户确有证据；无证据归入「不补」；
- 低代码平台 / BI 看板 / RPA 等「听起来高级」的词，**用户没明确做过不写**。
