# 简历改写文风规则（jobpilot-cn）

本文件规定“如何把用户的真实经历改写成高质量简历文案”。**核心铁律：只改写表达，绝不虚构。**

---

## 改写公式

每条经历用：**动作 + 对象 + 结果 + 数字**

- ❌ 差：“负责客户开发与维护”
- ✅ 好：“独立开发 30+ 海外客户，年回款 120 万，复购率 38%”

## 动词库（优先用强动词）

搭建 / 设计 / 主导 / 落地 / 优化 / 提升 / 降低 / 实现 / 打通 / 推动 / 从 0 到 1 / 统筹 / 对接

## 量化要求

- 每条 bullet 尽量带数字（金额、百分比、数量、时长、人数）
- 没有数字时，用“规模 / 范围 / 频率”替代（如“覆盖 5 个业务线”）
- **不可编**：没有的数字不编，没做的项目不加；缺失的标注“待补充”让用户确认

## 项目维度写法（讲清因果，不假大空）

STAR 只是描述单条经历的**结构皮**，真正要讲清的是「问题 → 目标 → 动作 → 效果」之间的**因果关联**。简历最大的问题是假大空——想体现好效果，就把**项目**写上去，项目天然自带问题、动作、结果。

每条项目 / 重点经历按四问展开：

1. **面对什么问题（痛点）**：现状的代价是什么？（耗时？漏检？成本高？）
2. **做了哪几步动作**：分步、可回溯，不用“负责/参与”糊弄。
3. **提升了什么指标**：金额 / 百分比 / 数量 / 时长。指标**不硬编但要挖**——很多经历不是没数字，是没去挖（处理多少询盘、覆盖多少 SKU、节省多少工时）；缺失标「待补充」。
4. **价值论证（高级写法，决定“好不好”）**：
   - 解决了什么痛点？
   - 为什么有效 / **不用更优方案（如不用 AI）行不行**？——能讲清“为什么没用更花哨的方案”恰恰证明你做的是工程决策而非跟风。
   - 你**抓住的核心**是什么？

### 角色诚实定位（不硬装主导）

- **主导型**：写清问题定义、架构 / 方案选型、关键决策与取舍。
- **辅助 / 执行型**：老实写你真实做的**专业动作**——怎么调 prompt、怎么做评测、指标怎么定义（降本？提效？准确率？），而非把团队成果写成个人独占。把执行动作讲专业，本身就证明能力。

> 误区：堆 STAR 格式但各段无因果 = 流水账；硬装主导却答不出核心 = 露怯。

## 对齐 JD

- 评估时提取 JD 的**关键词**，在简历中优先使用 JD 同款动词与术语
- 把与 JD 最相关的经历**前置**，弱相关的后置或精简
- 不改事实，只调整**措辞、顺序、强调点**

## 一页式原则

- 中文简历控制在一页 A4
- 社招：重结果数字；校招：重实习 / 学校 / 项目
- 删冗余、合并同类、去掉与岗位无关的内容

## 诚实边界

- 个人项目 / 副业如实标注性质，不伪装成企业级交付
- 技能水平如实写（熟练 / 项目接触 / 了解），不夸大
- 面试可能被深挖的点，文案留有余地，不写死无法解释的内容

## 禁忌

- 不写虚假公司、虚假职位、虚假业绩
- 不把团队协作成果写成个人独占（除非确为个人主导）
- 不用无法证实的超级lative（如“全国第一”）

## 白话 intake 规则（用户看不懂术语，必须用大白话）

使用者（尤其非技术 / 非 HR 背景）看不懂 `core_capabilities` / `summary` / `STAR` 这类英文黑话。发给用户的填表与提问一律用大白话，绝不让使用者接触内部术语。

**用户视角字段映射（agent 发的时候翻译）**：

| 内部字段 | 发给用户的大白话 |
|----------|------------------|
| core_capabilities | “你最拿手的几样本事 / 你比别人强在哪” |
| experience | “你工作过的地方，干了啥、带来啥结果” |
| projects | “你牵头做成的一件事 / 一个具体成果” |
| summary | “用两三句话介绍下你自己” |
| skills | “你会哪些本事、用过哪些工具” |

- 禁止向用户裸抛：`core_capabilities`、`summary`、`STAR`、`量化公式`、`验收红线`——这些是我们内部语言，写给程序或给 agent 看。
- **每个模糊栏目配 2–3 个例子**，尤其「项目经历」要说清“普通人做的哪些事也算项目”：一次促销 / 地推、谈下一个难搞的客户、带飞一批学员、搞定一次大客户投诉、组织一次团建 / 比赛 / 志愿活动——“凡是你牵头做成、有个结果的一件事，都算项目，别空着”。

## 访谈与挖掘问题清单（intake 阶段主动问，不是发张骨架等填）

### 1. 成就挖掘（用户常忽略的可写故事）
- 你做过最有成就感 / 最骄傲的一件事是什么？
- 最难处理的一次（客户 / 项目 / 冲突）你是怎么搞定的？
- 有没有一次超额完成任务？超了多少？

### 2. 数字 context（每条经历都追问）
- 这个数字是你个人的，还是团队的？你在里面排前几？
- 有没有比这更亮眼的数字可以写？（避免用弱数字代表候选人）

### 3. 软资产 / 爱好 / 志愿挖掘（转行或弱相关经历的救命桥接）
- 你平时有啥爱好？比如运动、拍抖音、玩无人机、写东西、搞副业——**说出来我帮你判断放哪块**（举例子点出“这也算”）。
- 在学校 / 上一份工作带过新人、做过培训吗？
- 参加过社团、志愿、比赛、兼职吗？

### 4. 动词升级
- 把“负责 / 参与 / 协助”换成强动词：主导 / 搭建 / 落地 / 从 0 到 1 / 统筹 / 对接。

## 爱好 / 兴趣的挖掘与路由（schema 已加 `interests` 字段）

用户常以为“爱好”只是摆设，其实它是**桥接素材**。agent 必须主动问、并举例子点出“这也算”。拿到爱好后做**迁移价值路由**，而不是原样堆在角落：

| 爱好 | 翻译出的简历价值 | 路由到 |
|------|------------------|--------|
| 攀岩 | 抗压、目标感、专注 | 核心能力 / 一句话总结 |
| 抖音自剪 | 短视频内容创作、剪辑 | 技能 |
| 玩无人机 / 航拍 | 直接命中求职方向 | 项目 / 技能 |

路由后的价值写进对应板块；`interests` 字段仅原样存原始爱好（详见 `schema x-intake-coaching`）。

## summary 重派生铁律

- 任何经历 / 项目 / 技能的增删之后，**必须重算 summary**：用最新最强数字 + 桥接人设。
- 禁止 stale summary：绝不能让旧弱数字（如已被新经历更强数字覆盖的）残留在总结里。
