# 简历改写文风规则（jobpilot-cn）

本文件规定“如何把用户的真实经历改写成高质量简历文案”。**核心铁律：只改写表达，绝不虚构。**

---

## 改写公式

每条经历用：**动作 + 对象 + 结果 + 数字**

- ❌ 差：“负责客户开发与维护”
- ✅ 好：“独立开发 30+ 海外客户，年回款 120 万，复购率 38%”

## 动词库（优先用强动词）

搭建 / 设计 / 主导 / 落地 / 优化 / 提升 / 降低 / 实现 / 打通 / 推动 / 从 0 到 1 / 统筹 / 对接

## 量化要求

- 每条 bullet 尽量带数字（金额、百分比、数量、时长、人数）
- 没有数字时，用“规模 / 范围 / 频率”替代（如“覆盖 5 个业务线”）
- **不可编**：没有的数字不编，没做的项目不加；缺失的标注“待补充”让用户确认

## 项目维度写法（讲清因果，不假大空）

STAR 只是描述单条经历的**结构皮**，真正要讲清的是「问题 → 目标 → 动作 → 效果」之间的**因果关联**。简历最大的问题是假大空——想体现好效果，就把**项目**写上去，项目天然自带问题、动作、结果。

每条项目 / 重点经历按四问展开：

1. **面对什么问题（痛点）**：现状的代价是什么？（耗时？漏检？成本高？）
2. **做了哪几步动作**：分步、可回溯，不用“负责/参与”糊弄。
3. **提升了什么指标**：金额 / 百分比 / 数量 / 时长。指标**不硬编但要挖**——很多经历不是没数字，是没去挖（处理多少询盘、覆盖多少 SKU、节省多少工时）；缺失标「待补充」。
4. **价值论证（高级写法，决定“好不好”）**：
   - 解决了什么痛点？
   - 为什么有效 / **不用更优方案（如不用 AI）行不行**？——能讲清“为什么没用更花哨的方案”恰恰证明你做的是工程决策而非跟风。
   - 你**抓住的核心**是什么？

### 角色诚实定位（不硬装主导）

- **主导型**：写清问题定义、架构 / 方案选型、关键决策与取舍。
- **辅助 / 执行型**：老实写你真实做的**专业动作**——怎么调 prompt、怎么做评测、指标怎么定义（降本？提效？准确率？），而非把团队成果写成个人独占。把执行动作讲专业，本身就证明能力。

> 误区：堆 STAR 格式但各段无因果 = 流水账；硬装主导却答不出核心 = 露怯。

## 对齐 JD

- 评估时提取 JD 的**关键词**，在简历中优先使用 JD 同款动词与术语
- 把与 JD 最相关的经历**前置**，弱相关的后置或精简
- 不改事实，只调整**措辞、顺序、强调点**

## 一页式原则

- 中文简历控制在一页 A4
- 社招：重结果数字；校招：重实习 / 学校 / 项目
- 删冗余、合并同类、去掉与岗位无关的内容

## 诚实边界

- 个人项目 / 副业如实标注性质，不伪装成企业级交付
- 技能水平如实写（熟练 / 项目接触 / 了解），不夸大
- 面试可能被深挖的点，文案留有余地，不写死无法解释的内容

## 禁忌

- 不写虚假公司、虚假职位、虚假业绩
- 不把团队协作成果写成个人独占（除非确为个人主导）
- 不用无法证实的超级lative（如“全国第一”）
